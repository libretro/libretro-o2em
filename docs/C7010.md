# Philips Videopac C7010 Chess Module

This core supports the C7010 Chess Module cartridge and its external NSC800
processor, 8 KiB firmware, 2 KiB RAM and communication latches. Detection uses
cartridge CRC32 `77066338`; the additional hardware is inactive for other games.

## Required files

Place the console BIOS `o2rom.bin` and the module firmware `c7010_z80.bin`
(8192 bytes) in the libretro frontend's system directory. Load the C7010
cartridge normally. Neither BIOS, module firmware nor cartridge data is
included in this repository. Users must supply their own copies.

Firmware is read through libretro's file interface. A missing or short module
firmware file causes content loading to fail with a log message rather than
running an incomplete module.

## Region and controls

Use **Console Region = Auto** or **PAL**. Auto resolves C7010 to PAL; explicit
region settings remain available. Auto also recognizes European Videopac/Jopac
filename prefixes `vp_`, `pal_` and `jo_`, as in the contributed implementation.

The console keyboard is used to start the game, select its options and enter
moves. A tested sequence is `1`, `Y`, `1`, Enter, followed by `E2E4`, Enter.
Wait for the computer's reply before entering the next move.

RetroArch can bind **E** to held slow motion and **F** to fullscreen switching.
Those frontend shortcuts may act at the same time as the emulated keyboard:
slow motion changes the perceived pitch/duration of E's beep, and F changes
the window size. These are frontend bindings, not key-specific sound defects.

Use RetroArch's Game Focus mode, rebind conflicting hotkeys, or use a
game-specific override. For content named `vp_C7010.bin`, the relevant entries
in `config/O2EM/vp_C7010.cfg` are:

```ini
input_hold_slowmotion = "nul"
input_toggle_fullscreen = "nul"
```

Do not disable shortcuts globally merely to configure this game. Reload the
content after changing an override. Other frontends can expose their own
equivalent keyboard-focus controls.

## Save states

The module's versioned `C7S1` block stores its CPU, RAM, latch and execution
state in explicit little-endian fields, with CRC32 validation. The immutable
firmware is identified by size and hash rather than embedded in a save state.
Loads reject a corrupt, truncated or mismatched-firmware module block before
applying it. A C7010 load cannot use a pre-module state without that block.
The existing non-C7010 legacy state path remains available.

## Implementation and validation

The integration keeps the established C7010-specific PAL beam/T1 and fractional
frame schedule, NSC800 interleaving, VDC character snapshots and portable
module state from the O2EM-NG libretro implementation. Graphics use the digital
palette for C7010, explicit character/sprite bit masks, corrected quad height,
and reject parked coordinate quads below the active major-object area.
No E-specific or F-specific audio/timing workaround is implemented in the core.

Windows x64 validation uses an isolated RetroArch configuration and user-owned
BIOS/firmware/cartridge files. The established regression sequence includes
E2-E4, D2-D3, G1-F3, F1-E2 and B1-C3 with computer replies, plus save/load and
comparison with the user-approved implementation. The standalone tests below
use only generated data and can be redistributed:

```sh
cc -std=c99 -O2 -Isrc tests/c7010_pal_test.c src/c7010_pal.c -o c7010_pal_test
./c7010_pal_test
cc -std=c99 -O2 -Isrc -Ilibretro-common/include tests/c7010_state.c src/c7010.c -o c7010_state_test
./c7010_state_test
```

The interpreter is validated for the C7010 firmware; unsupported opcodes are
logged and stop module execution. General-purpose Z80 software is outside
the validation scope.

Linux/ARM/console runtime behavior and WebAssembly require separate platform
validation. Retro Vault has offered future independent WebAssembly and scripted
gameplay testing; those results are not claimed here.
